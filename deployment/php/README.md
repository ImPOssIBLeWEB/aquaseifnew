# MAX-бот и форма — инструкция по развёртыванию

**Демонстрационный сайт на GitHub Pages не выполняет PHP.** Даже если файл обработчика присутствует в репозитории, форма на Pages должна оставаться выключенной. Секретов в коде нет.

На настоящем хостинге требуется PHP 8.1+, модули cURL и JSON и исходящий доступ к платформе MAX по HTTPS.

Подключение:
1. Создать бота в MAX для бизнеса, активировать его и получить API-токен. Получатель должен начать диалог с ботом (или добавить бота в чат), после чего его ID можно получить через события API.
2. В защищённых переменных окружения хостинга задать MAX_BOT_TOKEN, MAX_RECIPIENT_TYPE (user или chat) и MAX_RECIPIENT_ID. Не сохранять токен в репозитории, HTML, JS и файлах в публичной папке сайта.
3. Скопировать deployment/php/api/lead.php в /api/lead.php на PHP-хостинге. Фотографии и файлы этим обработчиком не принимаются.
4. Заменить демонстрационную privacy.html утверждённой политикой с реквизитами оператора и положениями об обработке данных через MAX и веб-аналитику.
5. Только после настройки бота, политики и тестов поставить в корневом index.html data-forms-enabled="true". На GitHub Pages оставить false.
6. Проверить отправку реальной тестовой заявки, неверный номер, ограничение частоты и ошибку MAX. При недоступности MAX обработчик **не** возвращает ложный успех, а предлагает позвонить.
7. Перед запуском рекламы рекомендуется настроить резервный канал (например, уведомления на почту или очередь), чтобы недоступность MAX не приводила к потере заявок. Здесь БД отсутствует.

Официальная документация: https://dev.max.ru/docs-api/methods/POST/messages

Обратите внимание: для отправки в личный диалог используется параметр user_id, для группового чата — chat_id. Сертификат и TLS должны быть настроены по актуальным требованиям MAX, отключать проверку сертификата нельзя.
